# 销售费用报销管理工作台 · 部署与运维说明

面向部署实施与运维同学。不需要懂 Python / Node，只需要会用 Docker 与命令行。

---

## 一、部署前要知道的三件事

1. **一台机器就够了**。数据库、后端、前端全在同一台主机的 Docker 里，不需要额外装 PostgreSQL。
2. **两条数据生命线**（后面会反复提到）：
   - **数据卷**：业务数据与发票影像，备份 = 导出数据库 + 拷走影像卷；
   - **`MAIL_SECRET`**：存在 `.env` 里，用来加密邮箱授权码。**它丢了，库里存的邮箱密码就永远解不开**，只能重新录入。所以密钥备份必须与数据备份**分开存放**。
3. **端口**：默认 8080。同一个网络里如果已经有服务占着，用 `--port` 换一个。

### 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Linux（Debian/Ubuntu/CentOS 均可）、macOS。Windows 请用 WSL2 |
| Docker | Docker Engine ≥ 20.10（更低也能跑，安装脚本会自动放宽 seccomp 策略，见第五节） |
| Docker Compose | v2（`docker compose`），Docker Desktop 自带 |
| 内存 | ≥ 2 GB 可用（数据库 + 应用 + 本地 OCR） |
| 磁盘 | ≥ 5 GB（镜像约 1 GB，其余留给数据与影像） |
| 网络 | 装完即可离线使用。目标机若无外网，用第六节的离线安装包 |

## 二、一键部署（推荐）

把安装包整个目录拷到目标机，进目录运行：

```bash
cd reimburse-workbench-2.9.1
chmod +x install.sh
./install.sh
```

脚本会依次做四件事，每一步都可重复执行：

1. **环境自检** —— docker 是否可用、compose 是否够新、端口是否被占用；
2. **准备 `.env`** —— 首次自动生成随机数据库口令、`MAIL_SECRET`（32 字节）、初始管理员口令；
3. **选定镜像** —— 优先用本机已有镜像，其次导入包内 `images/*.tar.gz`，最后才现场构建；
4. **启动并等健康检查通过**，然后打印访问地址、登录账号与初始口令。

结束时长这样：

```
部署完成

  应用地址    http://127.0.0.1:8080/
  局域网访问  http://10.10.10.5:8080/    手机与其他电脑用这个
  版本        2.9.1 · OCR rapidocr   镜像来源：安装包内镜像

  登录账号    admin
  初始口令    Kx7mQp2Zt9Bd
```

> **首次登录会强制要求改口令。** 请立即把上面的初始口令收进密码管理器，别留在终端记录里。

### 常用参数

| 参数 | 用途 |
| --- | --- |
| `--port 8081` | 换对外端口 |
| `--name stg --port 8081` | **同机再起一套**：容器名与数据卷自动加后缀隔离，两套互不影响 |
| `--dir /opt/reimburse` | 程序仍在安装包目录，但 `.env` 与备份落到指定目录 |
| `--offline` | 只认包内镜像，绝不联网构建；没有可用镜像时直接报错退出 |
| `--build` | 强制在目标机现场重建镜像（改了源码或要换 OCR 开关时用） |
| `--tag 2.9.1` | 指定镜像版本（升级时用） |

## 三、装完先做三件事

1. **备份 `MAIL_SECRET`**：从 `.env` 里抄出来，存到与数据备份不同的地方。
2. **改掉管理员口令**：首次登录会被强制改；改完确认能重新登录。
3. **试一遍手机访问**：手机浏览器打开「局域网访问」那行地址；iPhone 用 Safari 的「添加到主屏幕」可装成 App 图标（Android Chrome 是「安装应用」）。

## 四、日常运维

所有命令在安装目录（`.env` 所在目录）下执行。

```bash
# 查看日志（-f 跟随）
docker compose logs -f app

# 重启 / 停止（数据保留）/ 启动
docker compose restart app
docker compose stop
docker compose start

# 备份数据库（含 30 份滚动保留）
./deploy/backup.sh

# 手动备份数据库到指定文件
docker compose exec -T db pg_dump -U workbench -d workbench | gzip > backup-$(date +%F).sql.gz

# 备份发票影像（命名卷，导出成 tar）
docker run --rm -v reimburse-uploads:/data -v "$PWD:/out" alpine \
  tar -czf /out/uploads-$(date +%F).tar.gz -C /data .
```

### 恢复

```bash
# 1) 恢复数据库（先停应用，避免写入冲突）
docker compose stop app
gunzip -c backup-2026-09-19.sql.gz | docker compose exec -T db psql -U workbench -d workbench

# 2) 恢复影像
docker run --rm -v reimburse-uploads:/data -v "$PWD:/out" alpine \
  sh -c 'rm -rf /data/* && tar -xzf /out/uploads-2026-09-19.tar.gz -C /data'

# 3) 起回来
docker compose start app
```

> 恢复数据库前**必须**确认 `.env` 里的 `MAIL_SECRET` 与备份时一致，否则邮箱授权码解不开。

## 五、升级

```bash
# 1) 先备份（重要）
./deploy/backup.sh

# 2) 把新版本安装包放到机器上，解压并进目录
cd reimburse-workbench-2.9.3

# 3) 用原来那个 .env 覆盖过来（保留数据库口令与主密钥），再装一次
cp /path/to/旧目录/.env .
./install.sh --offline
```

要点：

- **`.env` 必须沿用旧的**。重新生成会换掉数据库口令（连不上原数据）与 `MAIL_SECRET`（邮箱密码全部作废）。
- 数据库结构升级在容器启动时自动执行（Alembic 迁移），日志里会打印 `[migrate] …`。
- 升级后重新登录验证一遍；如果旧版本用了数据卷以外的存储方式，先看第六节的「改名/搬家」。
- **2.4.0 → 2.5.0 没有数据库结构变更**，纯应用层升级：助手从「只会起草报销单」扩到全系统
  （15 个只读工具 + 36 个写动作，按角色裁剪），并且对话改为「先查库再回答」。
  直接按上面的步骤替换镜像即可，不需要额外的数据迁移动作。
- **2.5.0 → 2.9.1 同样没有数据库结构变更**。主要变化：
  2.7.10 起新增报销单/发票打印（A4 版式）与 Jev AI 决策网关（可选配置）；
  2.7.11 修复打印预览里看不到 Data Matrix 的问题（打印窗口是 Blob 文档，
  相对路径接口无法解析，已改为绝对 URL）；
  2.7.12 码图瘦身：DM 只编码单号（≤26×26 单数据区，不再是四块拼接的样子），
  打印尺寸 22mm → 16mm；
  2.7.13 打印左下角只留 DM 码图，去掉「扫码核验」标签、编号姓名文字与底部系统名；
  **2.8.0 新增「扫码核验」功能**：用手机拍照或选图识别单据上的 Data Matrix，
  自动跳转到对应报销单 / 发票详情（详见下节）；
  **2.9.0 新增「系统更新」在线升级**：管理员在「系统参数」页即可检查新版本并一键升级
  （详见本节末的「在线升级」）；
  **2.9.1 修正 Jev 决策网关**：此前调用地址与请求体不符合 Vercel AI Gateway 的真实协议，
  「连通性测试」必然失败且不显示原因，现已改为正确端点并补齐错误诊断（详见第八节）；
  **2.9.2 重排「系统参数」页**：参数表格改为分组设置行（审批流程 / 异常与预警 / 收票与识别），
  `ai_recognize_on_ingest` 补进参数字典（此前裸显英文键名且渲染成数字框），开关改为真正的
  toggle，「当前生效」速览条上移到卡片头部。同一版本还**重发了一次安装包**，修掉首装脚本崩溃：
  `install.sh` 在干净机器上（本机还没有镜像）会因未初始化的变量直接报
  `IMG_SOURCE：未绑定的变量` 而中断——拿到 2026-09-24 17:25 之前生成的 2.9.2 包请重新取一份，
  应用镜像本身没有变化。无数据库结构变更，替换镜像后强刷浏览器即可。
  **2.9.3 修 ARM 机器上「服务起不来」**：镜像里的 Data Matrix C 库（libdmtx）以前只带了
  x86_64 那一份，在 ARM（aarch64）机器上现场构建时会被装成一个用不了的库，日志里报
  `ImportError: Unable to find dmtx shared library`，而它是启动期导入的，**整个服务都起不来**
  （其实只有打印条码这一个功能是坏的）。现在镜像按本机架构装库、构建时就自检，装不对直接构建
  失败；即使库真的缺了也只影响条码接口（返回 503），服务照常运行。无数据库结构变更。
  打包脚本新增 `--image <tar.gz>`（可重复）：把另一种架构的镜像一起打进包，做出多架构安装包
  （`images/` 里按 `-linux-<架构>` 区分，安装脚本按 `uname -m` 自动挑本机那份）；
  **2.9.4 修表单排版**：弹窗里带文字的复选框（如「接入大模型」的「清除已保存的 Key」、
  「启用范围」）此前会被全局的 `.form-item input { width:100% }` 拉成整行宽的巨大方块，
  现已排除勾选框/单选框；「Jev 决策网关」配置表此前完全没有表格样式（浏览器默认裸渲染），
  已补齐键值表样式，手机端与数据表一样转成卡片；「调用用量」的统计范围控件修掉非法嵌套 label；
  手机端工具栏里的长说明文字不再占两行。无数据库结构变更，替换镜像后强刷浏览器即可。
  **2.9.5 重排手机端报销详情**：手机上打开报销单详情（以及所有用到「键值描述栅格」的弹窗）
  从「每个字段上下堆叠一小块」改为紧凑键值行——左标签右内容，虚线分隔；标题/事由/备注等长文本
  字段保持上下排；报销金额改为大字突出；「AI 体检」默认只占一行（说明文字收起，点按钮后照常
  展开）；明细/发票表的「合计」行合并为一行（左说明右金额）。另外全站时间显示去掉了中间的
  `T`（如 `2026-09-24T17:11` → `2026-09-24 17:11`）。无数据库结构变更，替换镜像后强刷浏览器即可。
  **2.9.6 修手机列表卡片**：手机上列表卡片（报销单/发票/异常预警/费用统计）此前有三种难看：
  数字列（金额/税额等）的左侧小标签被「继承的右对齐」顶到卡片中间；空值会渲染成一行孤零零的
  「—」（申请人下的部门、客户下的项目、发票代码等）；操作按钮行上方多一个没有信息量的「操作」
  小字。现均已修复：标签恒左对齐，空值不再渲染占位行，操作标签隐藏。无数据库结构变更，替换
  镜像后强刷浏览器即可。
  **2.9.7 修系统参数页报错与排版**：Jev 决策网关的配置（`jev_key`/`jev_base_url`/`jev_timeout_sec`）
  曾漏进系统参数页的「其他」组，被渲染成数字输入框——浏览器报
  `The specified value ... cannot be parsed` 且值被清空，保存还会被后端白名单 400 拒绝。
  现在系统参数页只展示本页可管理的参数（审批/预警/收票识别），Jev 配置仍在「AI 设置 →
  Jev 决策网关」维护（带密钥掩码）；控件兜底改为文本框，杜绝同类问题。排版上「更新于」
  从每行右侧独立一行收进名称行内，手机端隐藏更新时间与保存提示、数字框限宽 240px 不再撑满
  整屏。无数据库结构变更，替换镜像后强刷浏览器即可。
  **2.9.8 系统参数页视觉重做（桌面+手机）**：整页结构从「一条灰线通到底的平铺」改为三层：
  顶部「当前生效」改为三张指标卡（沿用统计看板 KPI 的左色条 + 图标 + 大号等宽数值，蓝/橙/紫
  三色区分二级审批门槛/超期预警/大额预警线）；每个分组独立成白面板卡（图标 + 标题 + 组内
  设置行），主体浅灰底衬托层次；参数行名称 15px、数字框右对齐等宽、开关状态改为绿/灰胶囊。
  底部操作条的「还原/保存」按钮推到右侧（此前 .spacer 未定义按钮挤在左边）。财务角色看到
  「只读」徽章与禁用控件。手机端指标卡单列、参数行上下堆叠、输入框限宽。无数据库结构变更，
  替换镜像后强刷浏览器即可。
  **2.9.9 系统更新改为独立页面**：原挂在「系统参数」页底部的「系统更新」卡片移出，成为独立
  页面（`#/upgrade`），入口在右上角用户菜单的「系统更新」项（仅管理员可见，财务/审批人/申请人
  无此项，直连地址也会被路由回看板）。页面重做：版本主卡（大号当前版本 + 状态徽章「已是最新/
  可升级/未配置」+ 检查更新与一键升级按钮 + 发布说明），下方「升级源配置」独立卡片改用与系统
  参数页一致的行式布局（不再是紧凑表格 + 折叠）。升级中的进度轮询行为不变。无数据库结构变更，
  替换镜像后强刷浏览器即可。
  包内没有本机架构的镜像时，安装脚本会 `warn` 一句后在目标机现场构建（原生架构、约 5-15 分钟、
  需要能访问 pip 源）。
  普通版本升级替换镜像即可，升级后建议用浏览器强刷一次（Ctrl/Cmd+Shift+R）；
  唯一的例外是 2.9.0 这一版，见下方警告。

> ⚠️ **升到 2.9.0 必须重跑一次安装脚本**。这一版给应用容器加了两个挂载
> （Docker socket 与升级卷），只换镜像不会生效——得让容器按新配置重建一次：
> `./install.sh`（或 `docker compose up -d --no-deps app`）。
> 这一次做完之后，后面所有版本都能在界面里一键升级。

### 扫码核验（v2.8.0）

系统左侧「业务办理 → 扫码核验」（手机端在底部标签栏第 4 个）。

- **拍照识别**（默认，内网 http 也能用）：点「拍照 / 选图识别」，手机直接唤起
  后置摄像头，拍下单据左下角的方码，自动识别并跳到对应记录。
- **实时扫码**：只有在 **https 或 localhost** 访问时才出现。
  浏览器规定网页调用摄像头必须处于安全上下文，内网 `http://IP:8080` 会被拒绝，
  所以内网默认走「拍照识别」，功能等价。
- 也可在页面右侧手工输入单号查询，最近 12 条扫描记录存在浏览器本地。

> **扫码提示**：本系统自带扫码识别（推荐）。另外 Data Matrix 也能用手机原生相机
> （iPhone / Android）或专用扫码 App（ZXing 条码扫描器、NeoReader）识别；
> **微信扫一扫不支持 Data Matrix**，只认二维码。若必须用微信核验，请说明，可切回 QR。

### 在线升级（v2.9.0+）

管理员在右上角用户菜单点「系统更新」进入独立页面（v2.9.9 起从「系统参数」页移出，
`#/upgrade`）：当前版本、最新版本、更新说明，以及「检查更新」「一键升级」两个按钮。
升级源是 GitHub Release。

**服务器侧（发新版的人）**——一条命令产出 Release 需要的三类文件：

```bash
./deploy/make-package.sh --tag 2.9.1 --release
# 产物 dist/release-2.9.1/：
#   manifest.json                                 版本清单（含 sha256）
#   reimburse-workbench-2.9.1-linux-amd64.tar.gz   镜像包
#   reimburse-workbench-2.9.1-app.tar.gz           骨架包（compose/install.sh/deploy/docs）
gh release create v2.9.1 -t "v2.9.1" -n "更新说明写这里，客户端会展示" dist/release-2.9.1/*
```

**目标机侧（升级的人）**——在界面上：

1. 「系统更新」→ 填「升级源仓库」（`owner/repo`）→ 保存配置
2. 点「检查更新」，确认目标版本与更新说明
3. 点「一键升级」，输入版本号确认后开始

升级过程中页面会中断 1~2 分钟（容器在替换），属正常现象；完成后页面自动恢复。
**流程与手动升级完全一致**：备份数据库 → 载入新镜像 → 更新 compose/install.sh
→ 更新 `.env` 的 `IMAGE_TAG` → 重建应用容器 → 健康检查。
**新版本没通过健康检查会自动回滚**到升级前的版本与镜像。

几个要点：

- **需要能访问 GitHub**。内网机器请在配置里填「拉包代理」（例如
  `http://10.10.10.252:1086`），或让它跟随 `AI_PROXY`。私有库还要填 GitHub 令牌。
- **升级前一版必须是 2.9.0 或更高**。2.9.0 之前没有 Docker socket 挂载，
  界面里的一键升级拿不到宿主 Docker，只能按第五节手动升上来。
- **macOS Docker Desktop 注意**：宿主侧的 socket 文件
  （`/Users/<你>/.docker/run/docker.sock`）bind 进容器后 **connect 会被拒**（Errno 111），
  `.env` 的 `DOCKER_SOCK` 必须填 VM 内部路径 `/var/run/docker.sock`；且该 socket 权限
  是 755、无组写位，只有 root 能连——`.env` 里设 `APP_USER=0:0` 让应用容器以 root 运行
  （v2.9.10+ 支持，默认仍是非 root 的 10001:10001）。
- **安全边界**：为「一键升级」，应用容器挂载了宿主机的 Docker socket，
  这等于把宿主机 root 权限交给这个容器。只在完全可信的内网开启；
  不需要在线升级时，把 `.env` 里的 `DOCKER_SOCK` 指向一个普通空文件即可关闭。
- 升级日志与下载的安装包留在 `reimburse-upgrade` 卷上；
  升级前的数据库备份也在里面（`docker volume inspect reimburse-upgrade` 可看位置）。

### Jev 决策网关（可选，AI 设置页）

「AI 设置」页底部的「Jev 决策网关」卡片：给 AI 助手接一个**只做判断、不写文字**的
快速决策模型（Vercel AI Gateway 上的 `typesafe-ai/jev`），用于发票分类、异常打分、
审批路由、重复检测。没配置或调用失败时 AI 自动退回大模型/规则，功能不受影响。

- 配置：填 Vercel AI Gateway 的 key（形如 `vck_…`，控制台 AI Gateway → API Keys 创建），
  保存即生效（5 秒内），无需重启。
- ⚠️ **Vercel 账号要先绑定信用卡**，否则网关一律返回 403（免费额度也要求绑卡）。
- 「连通性测试」会真的发一次最小决策：成功显示端点与耗时；失败时把 HTTP 状态码、
  网关原文、端点和建议一起列出来（如「需要绑卡」「key 无效」「可能是代理拦截」），
  照着提示处理即可。

### 换端口、换机器

- **换端口**：改 `.env` 里的 `APP_PORT`，`docker compose up -d` 重建即可。
- **换机器**：第三节的备份 + 恢复流程搬过去，别忘了 `.env`（尤其 `MAIL_SECRET`）。

## 六、离线部署（目标机没有外网）

在**有网且有 Docker** 的机器上打安装包：

```bash
./deploy/make-package.sh --tag 2.9.1
# 产物：dist/reimburse-workbench-2.9.1/（含镜像 tar.gz、源码、install.sh）
```

拷过去：

```bash
scp -r dist/reimburse-workbench-2.9.1 user@目标机:/opt/
# 或在源机：tar -C dist -czf - reimburse-workbench-2.9.1 | ssh user@目标机 'tar -C /opt -xzf -'
```

目标机上：

```bash
cd /opt/reimburse-workbench-2.9.1
./install.sh --offline
```

`--offline` 时安装脚本只认包内镜像，不会尝试联网。

**跨架构提醒**：镜像 tar 是「打包机的架构」，一个 tag 在一台机器上只能存一份镜像。安装脚本会按 `uname -m` 在 `images/` 里挑本机那份（文件名形如 `reimburse-workbench-<版本>-linux-<架构>.tar.gz`）；**包内没有本机架构的镜像时**，它会打印一句提醒然后**在目标机现场构建**（原生架构，需要能访问 pip 源；含本地 OCR 约 5-15 分钟），所以 ARM 机器拿到只带 amd64 镜像的包也能装，只是慢一点。想做成一个包通吃两种架构：在对应架构的机器上 `docker save reimburse-workbench:<版本> | gzip -1 > images/reimburse-workbench-<版本>-linux-<架构>.tar.gz` 放进去，或重新打包时加 `--image <那个 tar.gz>`。

## 七、常见问题

**Q：启动后访问不了？**
先看 `docker compose ps`，两个容器都应该是 `Up (healthy)`；再看 `docker compose logs --tail 100 app`。
最常见的原因是端口被占（换 `--port`）或防火墙没放行。

**Q：日志里报 `ImportError: Unable to find dmtx shared library`，服务起不来？**
这是镜像里的 Data Matrix C 库（libdmtx）不对：2.9.2 及以前的镜像里只有 x86_64 那份，
在 ARM（aarch64）机器上现场构建时必然踩到；而且这个异常发生在启动期导入阶段，
会把**整个服务**拖死（其实只有打印条码这一个功能是坏的）。换 2.9.3 及以后的安装包重装即可
（重跑 `./install.sh`；包内没有本机架构的镜像时，脚本会现场构建一个原生的，约 5-15 分钟）。
升级后 `curl http://localhost:8080/api/health` 应能看到 `"datamatrix":"ready"`；
万一仍是 `"unavailable"`，服务本身仍会正常运行，只有 `/api/print/dm` 会返回 503 并带上原因。

**Q：日志里出现「初始管理员已创建」，但我这不是第一次部署？**
说明应用的数据库是空的 —— 多半是连错了库：数据库卷被换过名字，或者 `.env` 里 `DATABASE_URL` 相关配置漏了。**先别继续往里录数据**，查清楚旧卷还在不在（`docker volume ls`），必要时按第四节的恢复流程导回来。

**Q：改了 `DB_PASSWORD` 之后起不来了？**
数据库卷里存的是旧口令，容器用新口令连不上。要么把 `.env` 改回旧口令，要么确认数据可弃后删卷重建：
`docker compose down -v && ./install.sh`（**删卷会丢光数据**）。

**Q：管理员口令忘了？**
在安装目录执行（会新建一个管理员账号）：

```bash
docker compose exec app python -c "
from app.database import SessionLocal
from app import models as m, security as sec
db = SessionLocal()
u = m.User(username='admin2', name='应急管理员', role=m.ROLE_ADMIN, active=True)
u.password_hash = sec.hash_password('临时口令@2026')
u.must_change_password = True
db.add(u); db.commit(); print('已创建 admin2')
"
```

登录 `admin2` 后到「用户管理」里重置原账号口令，再把 `admin2` 停用。

**Q：手机端页面是桌面版的样子？**
页面宽度 ≤820px 才会切手机版外壳（抽屉导航 + 底部标签栏 + 卡片列表）。平板/横屏大屏手机可能超过断点，属正常。

**Q：发票拍照识别不出内容？**
镜像里若带本地 OCR（`/api/health` 返回 `ocr_engine` 非空），拍照件与扫描件都能识别。识别不全时可以在「AI 设置」里接一个大模型做兜底补录。
